# SafeRoute AI — Data Directory

## Purpose

This directory stores all datasets used by the SafeRoute AI data ingestion pipeline.
Raw data is downloaded once and never modified. All cleaning, normalization, and
transformation produces derived files in `processed/`. Failed records go to `quarantine/`.

---

## Directory Layout

| Directory | Purpose | Expected Contents | Manually Editable |
|-----------|---------|-------------------|:---:|
| `raw/dataful/` | Dataful.in CSV exports | `blackspots*.csv` — 8,862 black spot records with official_id, chainage, state, district, managed_by, GPS (lat/lon ≈15%) | **No** — read-only provenance copy |
| `raw/morth/` | MoRTH annual publications | `RAI_20XX.pdf`, `RAI_20XX.csv` — Road Accidents in India reports (state/UT aggregate tables) | **No** — read-only provenance copy |
| `raw/opencity/` | OpenCity MoRTH dataset exports | `state_wise.csv`, `type_of_collision.csv`, `type_of_violation.csv`, `road_classification.csv`, `vehicle_type.csv` — per-dimension aggregate tables | **No** — read-only provenance copy |
| `raw/state/` | State-level police / department data | `*.csv`, `*.xlsx` — state-specific accident registers, FIR extracts (individual records) | **No** — read-only provenance copy |
| `raw/osm/` | OpenStreetMap exports | `*.osm`, `*.geojson`, `india-latest.osm.pbf` — road centerlines, highway geometries from Overpass API / Geofabrik | **No** — read-only provenance copy |
| `raw/irad/` | iRAD / e-DAR exports | `*.csv`, `*.json` — individual accident records with collision_type, cause, vehicle_type, GPS coordinates | **No** — read-only provenance copy |
| `processed/` | Cleaned, deduplicated, chainage-resolved files | `blackspots_enriched.csv`, `accidents_clean.csv`, `segment_risks.csv` — import-ready CSVs with resolved lat/lon | **No** — auto-generated by ETL scripts |
| `logs/` | ETL batch logs | `etl_*.log`, `import_summary_*.json` — per-batch run logs with record counts, errors, timing | Yes — for debugging |
| `quarantine/` | Rejected records from validation | `quarantine_*.csv` — rows that failed schema/validation checks during import | **No** — auto-generated |
| `metadata/` | Dataset catalogs and schemas | `catalog.json`, `checksums.txt`, `column_schemas/*.yaml` — source descriptions, file hashes, field definitions | Yes — for adding new sources |
| `exports/` | Generated output products | `calibration_points.csv`, `road_centerlines.db` — artifacts for downstream tools | **No** — auto-generated |

---

## Which Folders Must Never Be Edited Manually

| Folder | Rule |
|--------|------|
| `raw/*` | **Never modify, move, or delete** any file under `raw/`. These are the original source files. If a source needs re-downloading, place the new file alongside the old one and update the catalog. |
| `processed/` | **Never edit manually**. Always regenerate from raw sources via ETL scripts. |
| `quarantine/` | **Never modify manually**. Quarantined records should be analysed via the verification script or ETL logs, then re-imported after fixing the source or validation rules. |
| `exports/` | **Never edit manually**. Generated by build scripts. |

Folders `logs/` and `metadata/` are safe for manual inspection but prefer tooling.

---

## Dataset Lifecycle

```
Download → raw/<source>/ → (optional manual inspection) → ETL import →
  processed/ (clean data) ← → quarantine/ (rejected records) →
    RoadSegmentRisk builder → DB tables → routing engine
```

1. **Place** raw files in the appropriate `raw/<source>/` directory.
2. **Update** `metadata/catalog.json` with file name, hash, row count, date.
3. **Run** the corresponding importer: `python scripts/data_ingestion/<importer>.py raw/<source>/<file>.csv`
4. **Check** `logs/` for import summary and `quarantine/` for rejected records.
5. **Run** `python scripts/verify_datasets.py` to confirm all expected datasets are present.

---

## Notes

- The ETL framework tracks batch metadata in `backend/data/etl_metadata.db` (separate from this directory).
- Chainage-to-GPS resolution is performed at import time using the road centerline database (`exports/road_centerlines.db`).
- All paths in Python scripts resolve relative to the backend root; see `scripts/data_ingestion/etl_models.py` for the resolution pattern.
